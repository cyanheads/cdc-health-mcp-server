# 0.9.3 — 2026-10-07

## Changed

- **Tool and resource handlers no longer forward `ctx.recoveryFor`** — the framework fills a declared `errors[]` recovery hint on a bare `ctx.fail(reason, message)`, so the redundant spreads are gone from all five tools and both resources. Tests now assert recovery through `runToolContract` and `createWorkerHandler` via the new `tests/helpers/`.
- **Docker image installs production dependencies in a `$BUILDPLATFORM` stage** — the new `deps` stage cross-installs with `--os`/`--cpu`, runs `scripts/install-otel.ts`, then `scripts/prune-musl-packages.ts`; base images move to Bun 1.4.2.
- **`server.json` npm entries drop the `run start:*` package arguments and use `runtimeHint: npx`**; the HTTP entry now sets `MCP_TRANSPORT_TYPE=http`.
- **`.gitignore` and `.dockerignore` ignore `.env*`** (`.gitignore` keeps `.env.example`, `.env.template`, `.env.sample`); `.dockerignore` also excludes the MCP Registry token files and `.agents`; `.mcpbignore` excludes `docs/idea.md`, `logs/`, and `.cache/`.
- **The npm tarball excludes `dist/*.mcpb`** (`!dist/*.mcpb` in `package.json` `files`).
- **CodeQL workflow runs one job per language** (`actions`, `javascript-typescript`), each uploading under `/language:<language>`.
- **`.env.example` documents opt-in framework variables** — `MCP_REQUEST_STATE_KEY`, `LOG_TOOL_FAILURE_PAYLOADS`, `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES`, `LOG_LLM_INTERACTIONS`, `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`, `OTEL_EXPORTER_OTLP_METRICS_ENDPOINT`, `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`; the session-mode comment is reworded.
- **README tool descriptions condensed; badges updated** for MCP SDK `^2.2.0` and Bun 1.4.2. `CLAUDE.md` and `AGENTS.md` follow the framework's current error-contract, context, and release-flow text.
- **Scripts and `framework-skills/` resynced to mcp-ts-core 0.13.13** — `devcheck`, `lint-mcp`, `lint-packaging` (adds the Dockerfile build-platform check), `release-github` (adds `--check`), `check-skill-versions`, `check-framework-antipatterns`.
