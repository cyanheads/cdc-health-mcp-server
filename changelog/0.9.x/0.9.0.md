# 0.9.0 — 2026-09-20

## Added

- **`cdc_list_catalog_vocabulary`** ([#50](https://github.com/cyanheads/cdc-health-mcp-server/issues/50)) — lists the CDC catalog's `category` (55, whole) and `tags` (1,583, ranked and paged via `tag_limit`/`tag_offset`) vocabularies with entry counts, per allowlisted domain. `filter` narrows both before paging.
- **`cdc_discover_datasets` resolves near-miss `category`/`tags` filters** ([#50](https://github.com/cyanheads/cdc-health-mcp-server/issues/50)) — an empty page from a vocabulary-matched filter now names the closest catalog values with their entry counts instead of suggesting a broader search.

## Changed

- **`cdc_get_dataset_schema` and `cdc://datasets/{datasetId}` report a live `rowCount`** ([#46](https://github.com/cyanheads/cdc-health-mcp-server/issues/46)) — a parallel `count(*)` request replaces Socrata's `cachedContents.count`, which is built once and can understate an actively-updated dataset by a third or more; `rowCountSource` (`live`/`cached`) discloses which figure is in hand, falling back on a failed or slow count rather than failing the response.
- **`description` is returned in full as plain text** on `cdc_get_dataset_schema` and `cdc://datasets/{datasetId}`, and converted before truncation on `cdc_discover_datasets` — markup stripped and entity references decoded in one left-to-right pass (`src/utils/text.ts`), so the 300-character discovery budget is spent on visible text rather than tags and inline CSS.

## Fixed

- **`cdc_query_dataset` fails `not_queryable` on chart/map assets instead of returning empty rows as a paginated success** ([#45](https://github.com/cyanheads/cdc-health-mcp-server/issues/45)) — Socrata answers those IDs with HTTP 200 and rows of empty objects; the probe runs only when every returned row is fieldless, so a genuine null-only projection on a tabular dataset still succeeds with a notice. `access_denied`'s `when` now names `story`/`file`/`href`, the assets that actually 403.
- **HTML entities in CDC WONDER caveat/footnote text no longer double-decode** ([#51](https://github.com/cyanheads/cdc-health-mcp-server/issues/51)) — `xml-parser.ts` previously resolved `&amp;` before `&lt;`/`&gt;`, turning an already-escaped `&amp;lt;` into `<`; it now shares the single-pass decode with the Socrata description fix. Clears CodeQL alert #1 (`js/double-escaping`).
